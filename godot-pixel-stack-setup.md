# Стек вайб-геймдева: Godot 4 + Aseprite + Claude Code

**Инструкция для Claude Code.** Прочитай целиком, потом выполняй по порядку. Windows.
Профиль проекта: 2D пиксель-арт игры на Godot 4, Godot и Aseprite куплены в Steam.

Принцип стека: **петли обратной связи важнее количества инструментов.** Каждый компонент
здесь существует, чтобы агент видел результат своей работы, а не писал вслепую.

---

## 0. Если ты клонировал репозиторий

Стек уже установлен и разложен по этой инструкции 31 июля 2026. Всё, что можно
держать в git, лежит в git: аддоны, хук, `gdlintrc`, `.mcp.json`, скрипты. Заново
проходить разделы 1–5 не нужно — есть одна команда:

```bash
bash tools/setup_claude.sh
```

Она идемпотентна. Ставит то, что нельзя закоммитить (venv с gdtoolkit, Node-сервер
godot-mcp), и **проверяет** то, что не имеет права ставить за тебя (Godot, Aseprite):
находит их, печатает версии и точную строку для недостающего. Выходит с ненулевым
кодом, если чего-то не хватает.

Дальше — `bash tools/run_tests.sh`. Разделы ниже нужны, только если что-то пошло не
так или ты ставишь стек в другом проекте; **раздел 7 — карта путей этой машины**, а в
конце него список того, что в самой инструкции оказалось неверным.

Ничего машинно-специфичного в закоммиченных файлах нет. Все пути ищутся, любой можно
прибить гвоздём через переменную окружения:

| Переменная | Что задаёт | По умолчанию |
| --- | --- | --- |
| `GODOT` / `GODOT_CLI` | бинарник Godot | ищется, см. `tools/lib/find_godot.sh` |
| `GODOT_DIR` | куда распакован standalone | `C:/tools/godot` |
| `GODOT_MCP_SERVER` | собранный `index.js` моста | `C:/tools/godot-mcp/server/build/index.js` |
| `GODOT_MCP_PORT` | порт моста | `6505` |
| `GDLINT` | бинарник линтера | `.venv/Scripts/gdlint.exe`, затем PATH |
| `ASEPRITE` | бинарник Aseprite | ищется по типовым путям |

## Правила выполнения

1. Работай по шагам, не забегая вперёд. После каждого шага — его smoke-тест из раздела 6.
2. Все пути в Windows содержат пробелы. **Всегда** заключай их в кавычки.
3. Ничего не ставь глобально в систему без нужды. Python-пакеты — в venv проекта.
4. Если шаг падает — не чини молча и не выдумывай обход. Останови работу,
   покажи вывод ошибки и спроси.
5. Заполняй раздел 7 (карта путей) по ходу дела. Это артефакт, он нужен дальше.
6. Версии API у Claude Code меняются. Прежде чем писать конфиг хуков или плагинов,
   сверься с `https://docs.claude.com` — схема ниже может устареть.

## 1. Обнаружение и базовый инструментарий

### 1.1 Найти бинарники Steam

Не угадывай пути, найди их. Библиотека Steam может быть на любом диске.

```powershell
# Aseprite
Get-ChildItem -Path C:\,D:\ -Filter "Aseprite.exe" -Recurse -ErrorAction SilentlyContinue |
  Select-Object -First 5 FullName

# Godot
Get-ChildItem -Path C:\,D:\ -Filter "*odot*.exe" -Recurse -ErrorAction SilentlyContinue |
  Select-Object -First 10 FullName
```

Типовые расположения:
- `...\Steam\steamapps\common\Aseprite\Aseprite.exe`
- `...\Steam\steamapps\common\Godot Engine\`

Запиши найденное в раздел 7.

### 1.2 Второй Godot — консольный (важно)

**Это главная засада Windows.** Обычный `Godot.exe` собран как GUI-приложение и не пишет
в stdout. Все headless-команды (`--headless`, `--check-only`, прогон тестов, экспорт) будут
возвращать пустой вывод — агент не увидит ни ошибок, ни результатов тестов. Петля обратной
связи не заработает.

Решение: рядом со Steam-версией поставить standalone-сборку с `godotengine.org/download/windows`.
В архиве два экзешника:

| Файл | Назначение |
|---|---|
| `Godot_v4.x-stable_win64.exe` | GUI, для работы руками и для MCP-плагина |
| `Godot_v4.x-stable_win64_console.exe` | **CLI, для всех headless-команд и CI** |

Распакуй, например, в `C:\tools\godot\`. Steam-версию не трогай — она остаётся для ручной
работы и для MCP. Версия standalone должна совпадать со Steam-версией: проверь
`Help > About` в Steam-Godot.

Дальше в документе: `$GODOT_GUI` — Steam-версия, `$GODOT_CLI` — консольная standalone.

### 1.3 Toolchain

Проверь наличие, поставь недостающее:

```powershell
node --version    # нужен >= 18, для MCP-серверов
python --version  # нужен >= 3.10, для gdtoolkit
git --version
go version        # только если ставишь pixel-mcp из исходников, см. 4.1
```

Ставить: `winget install OpenJS.NodeJS.LTS`, `winget install Python.Python.3.12`,
`winget install Git.Git`, `winget install GoLang.Go`.

После установки — **новое окно терминала**, иначе PATH не подхватится.

## 2. Сторона Godot: аддоны в проект

Все три ставятся в `<проект>/addons/`. Коммить в git — да, они часть проекта.

### 2.1 Aseprite Wizard — мост Aseprite → Godot

Самый важный компонент стека. Убирает ручной экспорт спрайтов целиком: сохранил
`.aseprite` — в Godot обновилось. Теги Aseprite становятся анимациями, длительность
кадров в мс конвертируется в FPS Godot.

```powershell
git clone https://github.com/viniciusgerevini/godot-aseprite-wizard.git temp-wizard
Copy-Item -Recurse "temp-wizard\addons\aseprite_wizard" "<проект>\addons\"
Remove-Item -Recurse -Force temp-wizard
```

Включить: `Project > Project Settings > Plugins > Aseprite Wizard > Enable`.

**Обязательный шаг конфигурации:** в настройках плагина указать путь к `Aseprite.exe`
из раздела 7. Без этого плагин молча не работает.

Включи автоимпортеры, которые нужны для 2D:
- **Aseprite SpriteFrames** — основной, для `AnimatedSprite2D`
- **Aseprite Tileset Texture** — для файлов с тайлмап-слоями, отдаёт `AtlasTexture`
  прямо в редактор тайлсетов

### 2.2 GdUnit4 — тесты

Ставится из Godot Asset Library (`AssetLib` в редакторе) или клоном
`MikeSchulze/gdUnit4` в `addons/gdUnit4`. Включить в Plugins.

### 2.3 godot-mcp — живой мост в редактор

Бесплатный, архитектурно эквивалентен платным аналогам: WebSocket в редактор,
интеграция с UndoRedo (важно — Ctrl+Z отменяет всё, что делает агент), автопарсинг
типов вроде `Vector2(100, 200)` и `#ff0000`, переподключение с откатом.

```powershell
git clone https://github.com/mkdevkit/godot-mcp.git C:\tools\godot-mcp
Copy-Item -Recurse "C:\tools\godot-mcp\addons\godot_mcp" "<проект>\addons\"
cd C:\tools\godot-mcp\server
npm install
npm run build
```

Включить плагин в Godot. Он добавит автолоады-мосты для инспекции, ввода и скриншотов
(они удаляются при выключении плагина).

Прочитай README репозитория перед настройкой — порт и имена переменных окружения
проверь по нему, не по этому документу.

## 3. Сторона Aseprite

### 3.1 Расширение (опционально, только если ставишь MCP Pro)

Если решишь позже купить Aseprite MCP Pro — его Lua-расширение под MIT лежит открыто
в `youichi-uda/aseprite-mcp-pro`, копируется в
`%APPDATA%\Aseprite\extensions\aseprite-mcp-pro\`. Но **по умолчанию это не ставим**:
Godot-интеграцию, ради которой его стоило брать, закрывает Aseprite Wizard бесплатно.

### 3.2 Палитры

Скачай 2–3 палитры с lospec.com в `.gpl` или `.aseprite-palette` и положи
в `%APPDATA%\Aseprite\palettes\`. Хорошие стартовые: PICO-8, Sweetie-16, Endesga-32.

Фиксированная палитра — не эстетическая прихоть, а ограничение для агента.
Качество пиксель-арта у модели заметно растёт, когда выбор цвета ограничен.

## 4. MCP-серверы

### 4.1 pixel-mcp (Aseprite)

Если он уже настроен на старой машине — просто перенеси конфиг и путь к бинарнику.
Если ставишь с нуля, `willibrandon/pixel-mcp` написан на Go, а `make` в Windows обычно
нет; собирай напрямую:

```powershell
git clone https://github.com/willibrandon/pixel-mcp.git C:\tools\pixel-mcp
cd C:\tools\pixel-mcp
go build -o pixel-mcp.exe ./cmd/...   # уточни путь к main по структуре репо
```

**Запасной вариант, если сборка Go капризничает:** `ayigityol/aseprite-mcp` ставится
одной командой `npm install -g aseprite-mcp` и покрывает те же задачи.

Конфиг требует `aseprite_path` — бери из раздела 7.

### 4.2 Итоговый `.mcp.json`

В корне проекта. Пути подставь реальные:

```json
{
  "mcpServers": {
    "godot-mcp": {
      "command": "node",
      "args": ["C:/tools/godot-mcp/server/build/index.js"]
    },
    "pixel-mcp": {
      "command": "C:/tools/pixel-mcp/pixel-mcp.exe",
      "env": {
        "ASEPRITE_PATH": "C:/Program Files (x86)/Steam/steamapps/common/Aseprite/Aseprite.exe"
      }
    }
  }
}
```

Прямые слэши в JSON работают в Windows и не требуют экранирования — используй их.

## 5. Сторона Claude Code

### 5.1 Godot-скилл

Старый репозиторий `Randroids-Dojo/Godot-Claude-Skills` **помечен как deprecated**.
Скилл переехал:

```
/plugin marketplace add Randroids-Dojo/skills
/plugin install godot
```

Проверь по README нового маркетплейса, не изменилось ли имя плагина.

Что он даёт: GdUnit4, экспорт в веб и десктоп, CI на GitHub Actions, деплой.
Чего не даёт: манипуляции редактором — это зона godot-mcp. Они дополняют друг друга.

**Не включай PlayGodot** из этого скилла: он требует кастомного форка Godot с ветки
automation. Слезать со стокового движка ради этого не нужно, у нас есть godot-mcp
для инспекции рантайма.

### 5.2 gdtoolkit — линтер

```powershell
cd <проект>
python -m venv .venv
.venv\Scripts\activate
pip install gdtoolkit
```

Добавь `.venv/` в `.gitignore`.

### 5.3 Хуки — главный форс-мультипликатор

Смысл: агент правит `.gd`, линтер сразу отвечает, агент чинит сам в том же ходу,
не дожидаясь, пока ты откроешь редактор. По влиянию на качество кода это сравнимо
с MCP-сервером, а стоит вечера настройки.

**Сверь схему с актуальной документацией перед тем, как писать файл.** Ниже — форма,
которая была верна на момент написания; поля могли поменяться.

В `.claude/settings.json` проекта:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": ".venv\\Scripts\\gdlint.exe \"$CLAUDE_FILE_PATHS\""
          }
        ]
      }
    ]
  }
}
```

Требования к реализации:
- Хук срабатывает **только на `.gd`**. Фильтруй по расширению внутри команды —
  иначе он будет запускаться на каждой правке markdown.
- Отдельный хук на `.tscn`: `$GODOT_CLI --headless --quit --path <проект>`.
  Ловит битые `ext_resource`, невалидные UID и сломанные node paths — ровно те ошибки,
  которые агент делает чаще всего при ручной правке сцен.
- **Обязательно ставь таймаут.** `godot --headless` умеет висеть, если сцена
  открывает диалог или уходит в бесконечный `_ready`. Зависший хук вешает сессию.
- Хук не должен блокировать работу при ненулевом коде возврата линтера —
  предупреждения это не повод останавливать агента.

### 5.4 `CLAUDE.md`

Самая дешёвая и самая недооценённая часть. В обучающих данных модели много Godot 3,
и без явного напоминания она регулярно скатывается в старый API. Создай в корне:

```markdown
# Проект: 2D пиксель-арт игра на Godot 4

## Godot 4, не Godot 3

- Сигналы: `signal.connect(callable)`. НЕ `connect("signal", obj, "method")`.
- `CharacterBody2D` / `RigidBody2D`. `PhysicsBody` больше нет.
- API слоёв столкновений изменился относительно Godot 3.
- `@onready`, `@export` — с собакой.
- Частицы: `GPUParticles2D` по умолчанию, не `CPUParticles2D`.
- Если сомневаешься в API — проверь по docs.godotengine.org, не по памяти.

## Спрайты

- Спрайты рисуются в Aseprite через pixel-mcp, PIL и другая генерация
  картинок кодом ЗАПРЕЩЕНЫ.
- Палитра фиксированная: <вписать>. Цвета вне палитры не использовать.
- Обязательный цикл: нарисовал → экспорт PNG в 8x nearest-neighbor → ПОСМОТРЕЛ
  на результат → поправил. Не отдавай спрайт, который не видел глазами.
- Проверка перед сдачей: читается ли силуэт, есть ли контур,
  один ли источник света.
- `.aseprite` — единственный источник правды. `.png` в git не коммитим,
  их делает Aseprite Wizard при импорте.

## Сцены

- Собирай сцены через godot-mcp, а не правкой .tscn текстом.
  Ручная правка .tscn — только когда MCP не покрывает случай.

## Тесты

- Логика игры покрывается GdUnit4. Прогон:
  `<GODOT_CLI> --headless --path . -s res://addons/gdUnit4/bin/GdUnitCmdTool.gd --run-tests`
- Использовать консольный экзешник, иначе вывода не будет.
```

## 6. Приёмка: smoke-тесты

Не отчитывайся об успехе, пока все строки не зелёные. Каждая проверяет **петлю**,
а не факт установки.

| # | Что проверяем | Как | Ожидаем |
|---|---|---|---|
| 1 | Aseprite CLI | `& "$ASEPRITE" -b --version` | номер версии |
| 2 | Godot CLI пишет в stdout | `& "$GODOT_CLI" --version` | номер версии, **не пустота** |
| 3 | GUI-экзешник молчит | `& "$GODOT_GUI" --version` | пусто — это норма, подтверждает 1.2 |
| 4 | Проект открывается | `& "$GODOT_CLI" --headless --quit --path <проект>` | код 0, без ошибок |
| 5 | Линтер | `gdlint` на заведомо кривом `.gd` | ненулевой код, внятное сообщение |
| 6 | Форматтер | `gdformat --check` на файле | отработал |
| 7 | GdUnit4 | прогон тестов из 5.4 | отчёт с числом тестов |
| 8 | Aseprite Wizard | сохранить `.aseprite` с 2 тегами в проект | появился `SpriteFrames` с двумя анимациями |
| 9 | godot-mcp жив | открыть проект в GUI, спросить агента дерево сцены | вернулось реальное дерево |
| 10 | godot-mcp пишет | попросить создать узел | узел появился в редакторе, **Ctrl+Z его убирает** |
| 11 | pixel-mcp | попросить нарисовать спрайт 16x16 и экспортнуть в 8x | агент показывает картинку и комментирует её |
| 12 | Хук на `.gd` | попросить агента внести правку с ошибкой стиля | линтер ответил в том же ходу |
| 13 | Хук на `.tscn` | сломать `ext_resource` руками, попросить правку | ошибка загрузки всплыла сразу |
| 14 | Сквозная петля | «нарисуй спрайт монетки, собери сцену с анимацией, покажи скриншот» | проходит без ручного вмешательства |

Тест 14 — единственный, который действительно важен. Первые тринадцать
существуют, чтобы понять, где он сломался.

### Что в этом документе оказалось неверным

Проверено при установке, исправлять документ не стал — здесь список поправок:

- **1.1** Aseprite и Godot из Steam — оба GUI-сборки. `& $exe --version` из PowerShell
  печатает пустоту у *обоих*, а не только у Godot. При перенаправлении в файл вывод
  появляется, поэтому старый `run_tests.sh` и работал: там всё уходило в `grep`.
- **2.1** Папка аддона называется `addons/AsepriteWizard`, а не `addons/aseprite_wizard`.
  Версия 9.8.0. Путь к Aseprite — **editor**-настройка, а не настройка плагина в проекте,
  и Steam-сборка Godot self-contained, так что её editor settings лежат рядом с экзешником,
  а не в `%APPDATA%`.
- **2.1** Отдельных переключателей «SpriteFrames» и «Tileset Texture» в 9.8.0 нет. Есть
  один `aseprite/import/import_plugin/default_automatic_importer` в настройках проекта
  (поставлен в `SpriteFrames`) плюс выбор импортёра на каждый файл в доке Import.
- **4.2** godot-mcp нельзя регистрировать глобально, и документ прав, что ему место
  в `.mcp.json` проекта. Node-сервер занимает порт 6505 сразу при старте, поэтому при
  user-scope записи каждая открытая сессия Claude лезет на тот же порт и все, кроме
  первой, падают с `EADDRINUSE` — снаружи это выглядит как «MCP подключён, инструментов
  нет». Проверено: сессия в другом проекте забрала порт, и здесь инструменты не появились.
  Даже с проектной записью мост достаётся только одной сессии за раз.
- **8** К списку граблей: **мост godot-mcp держит ровно одного клиента**, и побеждает
  последний подключившийся (`this.client = ws`, `server/src/godot-bridge.ts:29`). Запуск
  Godot в режиме редактора (`--import`, `--editor` — даже с `--headless`) при открытом
  редакторе поднимает второй экземпляр плагина, тот забирает слот, а на выходе обнуляет
  клиента и роняет мост. Сокет живого редактора при этом остаётся ESTABLISHED, так что
  его плагин ничего не замечает и не переподключается — лечится только перезапуском
  редактора. Прогоны из `tools/run_tests.sh` безопасны: это режим игры (`-s` или путь к
  сцене), редакторные плагины там не грузятся вовсе.
- **2.3** Два инструмента godot-mcp врут, и оба молча. `update_property` прогоняет
  значение через тайп-парсер, который возвращает путь `res://` обычной строкой, — то есть
  он не умеет ставить ни одно свойство-ресурс: строка присваивается, Godot её отбрасывает,
  а инструмент рапортует успех. `execute_editor_script` — это `Expression`, а не скрипт:
  ни `var`, ни нескольких выражений, ни синглтонов, и `load()` в нём не работает вообще.
  Ресурс в свойство пришлось прописывать правкой `.tscn` руками.
- **2.3** Godot 4.7 при открытии/сохранении переписывает старые `.tscn` и `.tres` в новый
  формат: проставляет `uid=` в `ext_resource`, добавляет `unique_id=` каждому узлу,
  переупорядочивает под-ресурсы. Смысл не меняется, но в `git status` это выглядит как
  правка. После работы через MCP проверяй `git diff` и откатывай то, чего не просил.
- **4.1** Go не нужен: плагин `pixel-plugin` уже принёс собранный
  `pixel-mcp-windows-amd64.exe`. Но его `.mcp.json` запускает `bin/pixel-mcp` — это
  bash-обёртка, которая на Windows не стартует, поэтому сервер молча не поднимался.
  Перенаправлен прямо на `.exe`. **Правка живёт в кэше плагина и слетит при его обновлении.**
- **5.3** `$CLAUDE_FILE_PATHS` больше нет. Хук получает JSON на stdin, путь —
  `tool_input.file_path`; из переменных окружения есть `$CLAUDE_PROJECT_DIR`. Для
  PostToolUse код возврата 2 не блокирует (инструмент уже отработал), а показывает
  stderr агенту — это ровно то поведение, которое здесь нужно.
- **5.3** `$GODOT_CLI --headless --quit --path <проект>` как проверка `.tscn` открывает
  главную сцену проекта, а не отредактированную. Вместо этого — `tools/hooks/check_scene.gd`,
  который грузит и инстанцирует именно её. И проверять только код возврата мало: сцена со
  сломанным `ext_resource` всё равно грузится в `PackedScene`, Godot лишь пишет ERROR и
  идёт дальше, поэтому хук ещё и читает stderr.
- **6** Тест 3 («GUI-экзешник молчит») на standalone-сборке не воспроизводится: она пишет
  версию и из GUI-экзешника. Молчит именно Steam-сборка.
- **pixel-mcp** ломается на путях с обратными слэшами: `save_as` с `C:\...` падает с
  `invalid character 'U' in string escape code`. Внутри он собирает Lua/JSON и не
  экранирует их. Везде передавать прямые слэши.
- **pixel-mcp** `add_frame` добавляет копию предыдущего кадра, а не пустой. Чтобы
  нарисовать другой силуэт, лишнее надо явно затереть цветом `#00000000`.
- **pixel-mcp** `apply_shading` отработал вхолостую: `success: true`, картинка не
  изменилась. Свет пришлось класть руками через `draw_pixels`.

## 8. Известные грабли Windows

- **Пустой вывод headless-команд** — взят GUI-экзешник вместо консольного. См. 1.2.
  Это причина примерно половины проблем в этом стеке.
- **`make` не найден** — при сборке Go-проектов вызывай `go build` напрямую.
- **Aseprite Wizard молчит** — не прописан путь к `Aseprite.exe` в настройках плагина.
- **MCP-сервер не подключается** — Godot должен быть **запущен** с включённым плагином.
  Мост живёт внутри редактора, при закрытом редакторе подключаться не к чему.
- **PATH не обновился** — открой новый терминал после `winget install`.
- **Пробелы в путях** — `Program Files (x86)` ломает всё, что не в кавычках.
  В PowerShell для запуска по переменной нужен оператор `&`.
- **Версии Godot разъехались** — Steam обновляется автоматически, standalone нет.
  После каждого обновления Steam проверяй `--version` у обоих.

## 9. Что сознательно не ставим

Чтобы не пришлось объяснять заново:

- **Aseprite MCP Pro ($10)** — единственное, ради чего его стоило брать
  (экспорт `.tres`/SpriteFrames для Godot), бесплатно и лучше делает Aseprite Wizard.
- **Godot MCP Pro ($15)** — перевес в инструментах сидит в 3D: меши, PBR, GridMap,
  навмеши, окружение. Для 2D это мёртвый груз. Вернуться к вопросу, если упрёшься
  в отсутствие тайлмап-инструментов или рантайм-анализа.
- **PlayGodot** — требует кастомного форка движка.
- **PIL / генерация спрайтов кодом** — запрещено в `CLAUDE.md`, см. 5.4.

## 10. Кандидаты на потом

Не ставить сейчас, но держать в виду:

- **LDtk** — редактор уровней с JSON-форматом, который агент правит напрямую.
  Радикально приятнее, чем `.tscn` с тайлмапами. Брать, когда уровней станет много.
- **jsfxr / rfxgen** — процедурные SFX, параметры — маленький JSON.
  Агент генерирует и итерирует звуки пачками.
